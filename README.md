# Остров. Продукт. Вкус

Рабочие материалы книги Егора Тарасенко о сахалинской кухне через локальный продукт и историю.

## Публикация на GitHub Pages

Книга публикуется из `docs/` одним workflow — `.github/workflows/pages.yml`. Он собирает контент, прогоняет тесты и выкладывает `docs/` как артефакт Pages. Если сборка или тесты падают, публикации не будет.

**Один раз в настройках:** репозиторий → **Settings → Pages → Build and deployment → Source: `GitHub Actions`**.

Важно не выбирать «Deploy from a branch»: книга лежит не в корне, и в этом режиме GitHub отдаёт `README.md` вместо сайта. На случай, если режим всё же останется «ветка / (root)», в корне лежит `index.html`-переадресация в `docs/`.

Адрес сайта: https://horaanlika-droid.github.io/opv/

Если сайт не обновился: вкладка **Actions → Deploy book to Pages** покажет, на каком шаге остановилось. Частая причина — в репозитории остался второй workflow, который забирает ту же группу `pages`; в этом репозитории он удалён.

## Цель

Практическая кулинарная книга с элементами гонзо-повествования. Важны точные практические сведения, личное присутствие автора, ясный современный визуальный язык и аккуратная работа с культурной историей Сахалина.

## Редакционные документы

- `EDITORIAL_PLAN.md` — концепция, редакторский аудит и план работы.
- `MANUSCRIPT.md` — **мастер-рукопись** книги. Вводные главы («Философия», «Кухня, которую сформировали море, лес и время», «Остров как состояние») — рабочая редакция автора от 24.11.2026 (`Ostrov_Produkt_Vkus_working_draft_2026-11-24.docx`), тексты автора перенесены без сокращений; продуктовые главы — исследовательские черновики, авторские заметки и рецепты оставлены маркерами. Заголовок главы на стр. 108 пока не установлен. Служебные главы («Как читать этот документ», «Редакторская карта: что ещё нужно сделать», «Содержание», «Шаблон продуктовой главы») в сайт и PDF не публикуются.
- `ILLUSTRATION_PLAN.md` — раскадровка всех иллюстраций: бытовые сцены, природные зарисовки, видовые таблицы, форматы, статусы и вопросы автору.
- `assets/scenes/` — «Островные сцены» (бытовая хроника); `assets/scenes/reference/` — исходные листы раскадровки автора. Манифест — `docs/content/scenes.json`.
- `assets/illustrations/` — новые иллюстрации.
- `LAYOUT_SPEC.md` — параметры цифрового макета и этапы подготовки.
- `layout/proof.html`, `layout/book.css` — HTML/CSS-проба полосы.
- `layout/build-proof.js` — сборка двухстраничного PDF-прототипа (`npm run build:proof`).
- `layout/build-book.js` — сборка рабочего PDF из `MANUSCRIPT.md`: обложка, содержание с автоматически рассчитанными страницами, все главы второго уровня и готовые продуктовые иллюстрации. Новые главы попадут в PDF при следующей сборке.
- `book-proof.pdf` — прежняя двухстраничная цифровая проба: исходная обложка и одна перевёрстанная внутренняя полоса.
- `book-draft.pdf` — генерируемый рабочий PDF, не финальная редакция и не файл для типографии. Собрать командами `npm install` и `npm run build:book`; другой путь можно передать как аргумент: `npm run build:book -- /path/to/output.pdf`. Редакционные маркеры, пустые места для рецептов и незаполненные главы сохраняются, а не маскируются под готовый текст.

В шаблон главы добавлена гонзо-сцена: репортаж от первого лица только из реального опыта автора. Маркер `[ГОНЗО-ЗАМЕТКА АВТОРА: …]` в PDF выделен цветной врезкой — это заметный запрос автору, а не выдуманное воспоминание.

## Визуальное направление

Современная авторская книжная графика: сначала сверяться с реальными фотографиями конкретного вида, точно передавать силуэт, пропорции, плавники и характерные отметины; не подменять один вид похожим. Поверх достоверной основы — свободная наивная тушевая линия, заметные акварельные заливки и растекания, мягкое размытие, неровный живой контур и немного небрежная ручная подача. Не делать стерильную векторную графику или идеально вылизанный натурализм. Палитра сдержанная, композиция современная и пригодная для книжной полосы.

Допустимо вдохновение северной островной средой, но не копировать конкретные традиционные узоры, сакральную символику, костюмы или изображения айнов. Культурные сюжеты и атрибуцию традиционных мотивов согласовывать отдельно; не использовать неопределённый «этнический стиль» как декор. На изображениях не размещать текст, подписи, логотипы, водяные знаки или выдуманные этнографические символы.

## Устройство книги: повествование и «Заметка шефа»

Книга разделена на две части, и это разделение — правило сборки, а не оформление.

- **Повествование** — история продукта, острова, сезона и людей. Читается подряд; вопросы автору и источники остаются при тексте.
- **«Заметка шефа»** — выбор и оценка качества, первичная обработка, хранение, профессиональные техники и авторский рецепт. Открывается по отдельной ссылке в шапке главы, выдвижной страницей, и не прерывает чтение.

Разделение делает `docs/assets/js/chapter-split.js`. Это **один файл на всю систему**: его используют сборка контента (`tools/build-content.js`), тесты, книга в браузере и админка. Правило не может разъехаться между сборкой и чтением. `tools/chapter-split.js` — только проброс для Node.

Правила, которые проверяются тестами (`test/editorial-structure.test.js`):

1. «На кухне» и «Рецепт» не остаются в тексте главы.
2. Рецепт никогда не выдумывается: если в рукописи его нет, заметка пишет, чего не хватает (масса, температура, время, выход), и оставляет место.
3. Редакционный запрет сильнее структуры: у тайменя и калужницы заметка открывается как позиция, а не как рецепт (`recipeState: "blocked"`).
4. Сезонный календарь различает три вещи: природный сезон, сбор/промысел и наличие на рынке. Последнее честно помечено «не подтверждено» — рукопись таких данных не содержит.
5. Таксономические пометки `[1]` не попадают в карточки поиска, район продукта указывается только там, где он назван в тексте главы.

Практическая часть в данных лежит рядом с полным текстом: `chapter.story`, `chapter.practical`, `chapter.recipeState` (`awaiting-author` | `blocked` | `ready` | `none`). Если файл контента отредактирован через админку и этих полей в нём нет, книга делит главу в браузере тем же правилом.

## Островные сцены и сезонная отметка

**«Островные сцены»** — бытовая хроника Сахалина внутри повествования (не галерея): соседский обмен, мешок устриц, крабы из морской воды, поездки за уловом, домашняя кухня, заготовки, семейный ужин, берег, разделка рыбы, возвращение, стол с продуктами. Двенадцать сцен расставлены по смысловым точкам текста:

- маркеры `[ИЛЛЮСТРАЦИЯ: id]` в `MANUSCRIPT.md` — привязка внутри главы;
- записи с `place` в `docs/content/scenes.json` — привязка к разделу («открытие» Моря, Леса, Дичи) или к соседней главе;
- изображения собираются из `assets/scenes/` в `docs/assets/scenes/*.webp` при `npm run build:content`;
- каждая сцена несёт метаданные (название, глава, точка размещения, тип, описание, источник визуальной информации, статус) — см. `ILLUSTRATION_PLAN.md`.

**Сезонная отметка** у названия продукта — короткая типографская подпись («Весна · основной сезон»), а не бейдж. Правила: различаются природный сезон, сбор/промысел и наличие на рынке; месяцы показываются только при подтверждении; неподтверждённый сезон честно помечен «сезон не установлен»; продукт нескольких сезонов показывает их все. Отметка ведёт к нужному блоку сезонного календаря. Логика в одном файле — `docs/assets/js/season-labels.js` (книга и тесты используют его же).

**Открытие главы** следует макету мобильной книги (`assets/reference/app-chapter-mockup.png`): номер «Глава NN», крупный заголовок, авторский лид, сборная акварельная сцена и вынесенная цитата. Копия открытия — только из макета автора (сейчас — «Философия»); ничего не сочиняется. Ниже — тихий индикатор прогресса «NN / 43». Подробности и статусы — в `ILLUSTRATION_PLAN.md`, раздел F.

## Шрифты

Гарнитуры — Cormorant Garamond (заголовки), Spectral (текст), Inter (интерфейс), лицензия SIL OFL (`docs/assets/fonts/OFL-*.txt`).

Fontsource режет шрифты по подмножествам: латиница, кириллица, latin-ext отдельно. Если взять один файл, в книге не будет либо кириллицы, либо цифр и латинских названий видов — и текст начнёт набираться двумя гарнитурами вперемешку. Поэтому `tools/build-fonts.py` склеивает `latin + cyrillic` в один woff2 на начертание и выбрасывает ненужные хвосты (вьетнамский, греческий).

```bash
pip install --break-system-packages fonttools brotli
npm install --no-save --prefix /tmp/fonts @fontsource/cormorant-garamond @fontsource/spectral @fontsource/inter
python3 tools/build-fonts.py
```

Итог: 11 начертаний, ~217 КБ, полный набор (кириллица, латиница, цифры, «ёлочки», тире, стрелки).

## Сайт книги и админ-панель

Книга публикуется как статический сайт на GitHub Pages из папки `docs/` (ветка `main`, папка `/docs`, сборка «Deploy from a branch»). Включение: **Settings → Pages → Source: Deploy from a branch → Branch: `main`, folder `/docs` → Save**; через минуту сайт доступен по адресу ниже.

- Сайт: https://horaanlika-droid.github.io/opv/
- Админка: https://horaanlika-droid.github.io/opv/admin/?pass=opv2026
- Исходные данные сайта: `docs/content/book.json` (заголовки, главы в Markdown, привязка иллюстраций)

### Сборка контента

```bash
npm install
npm run build:content   # MANUSCRIPT.md + assets/illustrations/*.png → docs/content/book.json и docs/assets/illustrations/*.webp
npm test                # проверка структуры book.json и Markdown-рендера
```

`build:content` берёт текст из `MANUSCRIPT.md`, поэтому правки, сделанные через админку, при повторной сборке перезаписываются. Если текст уже живёт в `book.json`, правьте его через `/admin` и снимайте правки оттуда (экспорт JSON) — либо переносите их в `MANUSCRIPT.md` до сборки.

### Админка

Вход — пароль в адресной строке (`?pass=opv2026`, `?password=opv2026` или `#opv2026`) либо в поле на экране входа. После входа сессия помнится в браузере до закрытия вкладки.

Что можно делать:

- редактировать заголовок и текст любой главы, добавлять, удалять и переставлять главы (`↑`/`↓`);
- вставлять заготовку продуктовой главы кнопкой «Шаблон» (места для авторского текста и источников помечены как `[СЛОТ]` и подсвечиваются);
- менять название книги, автора, подзаголовок и редакционное примечание (кнопка «Метаданные»);
- привязывать иллюстрации из списка `docs/assets/illustrations/`;
- смотреть предпросмотр в вёрстке книги;
- экспортировать/импортировать `book.json` (резервная копия без GitHub).

### Как сохраняются правки

GitHub Pages — статический хостинг, сервера нет, поэтому «Сохранить в GitHub» пишет `docs/content/book.json` напрямую через GitHub API:

1. Создайте personal access token (Settings → Developer settings → Personal access tokens) с правом записи содержимого репозитория: classic — scope `repo`; fine-grained — доступ к репозиторию `opv` и разрешение `Contents: Read and write`.
2. В админке откройте «GitHub» (шестерёнка в шапке), вставьте токен, нажмите «Проверить доступ», затем «Сохранить в GitHub» (или `Ctrl`/`Cmd` + `S`).
3. Токен хранится только в `localStorage` вашего браузера и отправляется исключительно на `api.github.com`. После сохранения GitHub Pages обновляется примерно за минуту.

Ветка и путь определяются автоматически по настройкам Pages (`docs/content/book.json`). Несохранённые правки дополнительно лежат в `localStorage` — при следующем открытии админка предложит их восстановить.

### Ограничение безопасности

Пароль `opv2026` проверяется в браузере, а сам код админки открыт в публичном репозитории — это защита от случайных посетителей, а не настоящая авторизация. Реальная защита содержимого — токен GitHub: без него админка ничего не запишет. Не публикуйте токен и не вставляйте его на чужих устройствах.

## Рабочие правила

- Не изображать как факты неподтверждённые виды, способы добычи, традиции или атрибуции.
- Не сочинять личный опыт автора; места для него оставлять в рукописи.
- Не придумывать рецепты: автор добавит их позднее.
- Имена файлов делать описательными и использовать отдельную папку для итоговых иллюстраций.
- Фактологические и культурные вопросы фиксировать в `EDITORIAL_PLAN.md` или `MANUSCRIPT.md`.
